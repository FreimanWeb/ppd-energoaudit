# Тарифы электроэнергии

SQLite-таблица `electricity_tariffs` хранит общую для объектов цену:

| Поле | Значение |
| --- | --- |
| `valid_from` | Первый день действия включительно, ISO `YYYY-MM-DD`, PRIMARY KEY |
| `valid_to` | Последний день действия включительно, ISO `YYYY-MM-DD` |
| `rub_per_kwh` | Конечная положительная цена в руб/кВт·ч |
| `source` | Обязательный источник цены |

Исходные периоды:

- **01.01.2025–31.12.2025 — 4,68 руб/кВт·ч**, указание пользователя от 18.10.2026.
- **01.01.2026–31.12.2026 — 5,17 руб/кВт·ч**, Н. Н. Алаева (ВШН), сообщение
  от 16.10.2026 08:49.

Миграция v11 переводит годовые записи v10 в диапазоны, сохраняя цены и источники.
Повторный запуск не перезаписывает существующие значения. Телеметрия и паспорта
при миграции не меняются. Пересекающиеся периоды repository не допускает;
изменение записи определяется датой начала.

Расчёт использует дату выбранного снимка. Выездная оценка использует текущую
дату (`Europe/Moscow`). Внутри периода цена применяется без предупреждения.
Вне всех периодов, включая промежутки между ними, выбирается тариф с ближайшей
границей. При одинаковом расстоянии выбирается более поздний период.
API возвращает `tariff_warning`, React показывает предупреждение
с выбранной датой, ценой и границами использованного периода.
Пустая таблица остаётся ошибкой: API возвращает 400, интерфейс предупреждает
о невозможности расчёта. Цена из YAML не подставляется.

Цена выбранной даты используется как постоянная на многолетнем горизонте;
она не считается прогнозом изменения тарифов. Физические потери и потребление
энергии от цены не зависят. В исходных математических функциях сохранены
прежние defaults для самостоятельных вызовов; приложения передают цену из БД.

```python
from datetime import date
from ppd_audit.db import AuditDatabase, default_database_path
from ppd_audit.services.catalog import tariff

db = AuditDatabase(default_database_path())
db.migrate()
print(tariff(date(2027, 1, 1), database=db))  # цена 2026 года и warning
```
